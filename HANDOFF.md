## What is done and verified

### Front end — done
`template.html` was rebuilt from the Claude Design handoff
(`beatass Design System-handoff.zip`, extracted design system: tokens, 18
components, mobile-first layout, upgraded doll engine). It was a React
prototype; this is plain HTML/CSS/JS in one file, per the house rule.

Verified by `npm test` (real Chromium, 7 viewports):

| Check | Result |
|---|---|
| No page scroll, 1440×900 → 360×640 | pass |
| Doll size on the smallest phone | 229px |
| GIF export | real `GIF89a`, ~670 KB |
| MP4 export | real `ftyp` MP4, ~260 KB, 1080×1920 |
| Validation, preview, send, reset flows | pass |
| Console / page errors | none |

Notable things built that were **not** in the design handoff (the handoff
README says "MP4 export and Web Share… not built here"):

- **MP4 export at 1080×1920.** Instagram and Snapchat both reject animated
  GIFs — hand them a `.gif` and it posts as a frozen still. Composed live into
  an off-screen canvas while you play, via `canvas.captureStream(0)` +
  `MediaRecorder` + `requestFrame()`, so it is finished the instant you stop.
  Falls back to GIF-only if the browser can't produce MP4
  (`pickVideoMime()` in `template.html`).
- **Web Share** with the file attached, plus save.
- **The share screen** at the end of the flow.

### Backend — written, infrastructure live, not deployed
`src/index.js`. Four routes: `POST /api/send`, `GET /media/:id`, `GET /block`,
`GET /report`. Abuse controls are in and are not optional: blocklist checked
before every send, 5 sends/hour/IP via KV, signed block + report links
(HMAC, constant-time compare), IPs stored only as salted hashes,
`List-Unsubscribe` header for deliverability.

## What is NOT done — in priority order

### 1. Wire the front end to the API  ← **start here**
`template.html`'s `send()` function currently just opens the sent overlay.
It needs to `POST /api/send` as `multipart/form-data` with fields
`name`, `email`, `message`, `stats`, and file parts `gif` and `mp4`
(both from `state.gifBlob` / `state.videoBlob`).

Handle: the 403 blocklist response, the 429 rate limit, and the 502 send
failure — each has a human-readable `error` string, show it rather than a
generic failure. Keep the share screen working when offline/failed.

Then delete the "prototype note — nothing was actually sent" line from the
sent overlay, which will no longer be true.

### 2. Deploy
```bash
python3 build.py && npx wrangler deploy
```
`wrangler.jsonc` serves `public/` as static assets (regenerated by
`build.py`; git-ignored) and falls through to the Worker for `/api/*`,
`/media/*`, `/block`, `/report`.

### 3. Verify the domain in Resend  ← **blocks real email**
Until `beatass.com` is verified inside Resend, mail can only be delivered to
the address that owns the Resend account (`unread.fyi@gmail.com`). Everyone
else silently gets nothing. `MAIL_FROM` in `wrangler.jsonc` is currently
`onboarding@resend.dev` and must change to an address on the real domain.

### 4. DNS at GoDaddy
The domain is registered at **GoDaddy**. Recommended (agreed, not yet done):
move the nameservers to Cloudflare, which is free and brings the WAF, bot
filtering and DDoS protection — worth having on an anonymous-message site.

Then add **SPF, DKIM and DMARC** (Resend gives the exact records). These are
free DNS entries and they are not optional: without them this mail goes
straight to spam no matter how good the subject line is, and with the full
confession inline the reputation risk is real.

### 5. SEO
Meta, OG and Twitter tags are already in `template.html` and reference
`https://beatass.com/og.png` — **that image does not exist yet.** Still to do:
`robots.txt`, `sitemap.xml`, the OG image, and structured data.

### 6. The personal link (`beatass.com/priya`)
Lowest priority, per the decisions table. See `DESIGN-PROMPT.md` Prompt 2.
If it gets built, store the doll's *choreography* (~500 bytes of instructions),
not the video — about 4,000× cheaper. That requires swapping `Math.random()`
in the doll engine for a seeded generator and storing the seed; build it in
from the start, retrofitting is painful.

## Decisions already taken — do not reopen

Full table at the bottom of `DESIGN-PROMPT.md`. The ones most likely to be
"helpfully" undone:

- **No age gate.** Raised twice, declined twice. An "18+" line in the footer
  is the extent of it.
- **The email carries the full confession inline**, with a catchy personalised
  subject. Deliberate. Not a link-only notification.
- **`beatass.com` stays.** No new domain.
- **Anonymity is permanent** — never revealed, never hinted at, never sold.
  The FTC fined NGL $5M partly for selling "hints" about senders.
- **Never fake a message** to make the product look busy. The other half of
  that same fine.
- **Report + block links stay in every email** and get more prominent, never
  less.

## House rules that will bite

- **Edit `template.html`. Never `beatass.html`** — it is generated and any
  direct edit is destroyed by the next `python3 build.py`.
- Run `npm test` after any layout, doll, or export change. It catches the two
  failure modes invisible in source: silent scrolling on small screens, and a
  broken encoder that still renders a plausible-looking `<img>`.
- One file, no framework, no bundler. No emoji as icons — icons are inline SVG
  in the `<defs>` block. Nothing is a perfect rectangle. Three inks only.
