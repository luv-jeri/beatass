- **The share screen** at the end of the flow.

### Backend — written, infrastructure live, not deployed
`src/index.js`. Four routes: `POST /api/send`, `GET /media/:id`, `GET /block`,
`GET /report`. Abuse controls are in and are not optional: blocklist checked
before every send, 5 sends/hour/IP via KV, signed block + report links
(HMAC, constant-time compare), IPs stored only as salted hashes,
`List-Unsubscribe` header for deliverability.

### Front end → API — done 2026-08-02
`send()` in `template.html` now posts `multipart/form-data` to `/api/send`
with `name`, `email`, `message`, `stats` and the file parts `gif` and `mp4`.

On a failure it shows the API's own sentence (403 blocked, 429 rate limit,
413 too big, 502 mail provider) in a red line on the preview, **and keeps the
preview open** — it never claims the message was sent when it wasn't. The
Send button re-enables so they can retry; Save is right there, so nothing
they made is lost. A total network failure gets its own line. The "prototype
note — nothing was actually sent" line is gone from the sent screen.

`npm test` covers both halves: the mock API is served at the real
`/api/send` path, refuses the first attempt (429) and accepts the second, and
the test asserts the error text appears, the sent screen does *not* open on
refusal, and the POST really carried every field plus real `GIF89a` bytes
(~930 KB). Mocking at the real endpoint is deliberate — the test breaks the
moment the page and the Worker's field names drift apart.

## What is NOT done — in priority order

### 1. Deploy  ← **start here**
```bash
python3 build.py && npx wrangler deploy
```
`wrangler.jsonc` serves `public/` as static assets (regenerated by
`build.py`; git-ignored) and falls through to the Worker for `/api/*`,
`/media/*`, `/block`, `/report`.

### 2. Verify the domain in Resend  ← **blocks real email**
Until `beatass.com` is verified inside Resend, mail can only be delivered to
the address that owns the Resend account (`unread.fyi@gmail.com`). Everyone
else silently gets nothing. `MAIL_FROM` in `wrangler.jsonc` is currently
`onboarding@resend.dev` and must change to an address on the real domain.

### 3. DNS at GoDaddy
The domain is registered at **GoDaddy**. Recommended (agreed, not yet done):
move the nameservers to Cloudflare, which is free and brings the WAF, bot
filtering and DDoS protection — worth having on an anonymous-message site.

Then add **SPF, DKIM and DMARC** (Resend gives the exact records). These are
free DNS entries and they are not optional: without them this mail goes
straight to spam no matter how good the subject line is, and with the full
confession inline the reputation risk is real.

### 4. SEO — done 2026-08-02, one item left
Built and verified:

| Piece | Where it comes from |
|---|---|
| `og.png` (1200×630) | `node tools/make-og.mjs` — the site's own doll and fonts, so the card can never drift from the site. Committed at the repo root; `build.py` copies it into `public/` |
| `robots.txt` | generated by `build.py`. `/block` and `/report` disallowed (a crawler must never click them); media deliberately NOT disallowed |
| `sitemap.xml` | generated by `build.py` from one list, so it cannot drift from the real pages |
| Structured data | `WebSite` + `WebApplication` + a 4-question `FAQPage`, as JSON-LD in `template.html`'s head. Valid JSON, checked by parsing the built file |
| OG / Twitter | `og:site_name`, image width/height/alt, explicit `twitter:title`/`description`/`image` |
| Privacy, Terms, About, Contact, 404 | source in `pages/`, wrapped by one shell in `build.py` so the footer links to all four legal pages from every page, permanently |
| Media noindex | `X-Robots-Tag: noindex, noimageindex` on `/media/*` in the Worker |

The one gate failure left is in the checker, not the site: the `legal-crawl` gate
turns `https://beatass.com/` into a filename by splitting on slashes, so it reads
the domain as a missing file. Making it pass would mean putting
`https://beatass.com/index.html` in the sitemap, contradicting the page's own
canonical tag. The sitemap was left correct and the gate bug was filed instead
(`evolution/inbox/2026-08-02-legal-crawl-gate-cannot-parse-root-url.md`). All the
gate's other checks (L1–L5, L7) pass.

**Still to do:** submit the sitemap to Google Search Console once the site is
live on the real domain. That cannot happen before the deploy and the DNS move.

## Decisions already taken — do not reopen

Full table at the bottom of `DESIGN-PROMPT.md`. The ones most likely to be
"helpfully" undone:

- **No age gate.** Raised twice, declined twice. An "18+" line in the footer
  is the extent of it.
- **The email carries the full confession inline**, with a catchy personalised
  subject. Deliberate. Not a link-only notification.
- **`beatass.com` stays.** No new domain.
- **Anonymity is permanent** — never revealed, never hinted at, never sold.
  The FTC fined NGL $5M partly for selling "hints" about senders.
- **Never fake a message** to make the product look busy. The other half of
  that same fine.
- **Report + block links stay in every email** and get more prominent, never
  less.

## House rules that will bite

- **Edit `template.html`. Never `beatass.html`** — it is generated and any
  direct edit is destroyed by the next `python3 build.py`.
- Run `npm test` after any layout, doll, or export change. It catches the two
  failure modes invisible in source: silent scrolling on small screens, and a
  broken encoder that still renders a plausible-looking `<img>`.
- One file, no framework, no bundler. No emoji as icons — icons are inline SVG
  in the `<defs>` block. Nothing is a perfect rectangle. Three inks only.

## Open questions for Sanjay

### A mail scanner can block a recipient who never clicked  ← the serious one
`/block` and `/report` both act on a **GET**. Corporate mail security (Microsoft
Defender SafeLinks, Proofpoint, and others) opens every link in an incoming email
to check it is safe, before the human sees the message. When that happens here,
the scanner silently blocks that address forever, or files a report — and the
recipient never receives another beatass message, without ever having clicked
anything. They will not know why, and there is no unblock endpoint by design.

Not urgent today, because nothing is deployed and no real mail has gone out. It
must be settled before the first real send. The standard fix is to make the link
open a page with a confirmation button, and do the actual blocking on a POST
from that button — one extra click for the human, invisible to the scanner. That
changes the "one click and it's done" promise written into the email, the
privacy page and the contact page, so it is a product decision, not a patch.

### hello@beatass.com does not exist yet
The legal pages all point at `hello@beatass.com`. That address was chosen so
Sanjay's personal Gmail is not published on an anonymous-message site — but it
routes nowhere until Cloudflare Email Routing is switched on, which needs the
nameservers moved first (job 3). Until then, mail to that address bounces. Either
finish the DNS move, or swap the address in `pages/*.html` for one that works today.


### The caption disagrees with itself when the doll was loved
The preview shows one of two captions: "…and this is what they did to you.
(stats)" normally, or "…and this is how they feel about you." when the visit
was mostly loving. The email in `src/index.js` only ever writes the first one,
because all it receives is `stats`. So a loving message arrives captioned as an
assault. Two ways to settle it: send the finished caption instead of `stats`
(front end decides, one field change on both sides), or teach the Worker the
same rule. It is a copy decision, so it was left alone. Found 2026-08-02.


The design handoff's README describes a phone layout where the doll comes
first and the page scrolls; the actual `AppScreen.jsx` puts the recipient
fields first with `overflow:hidden`. **The code was followed**, with the
content column made to scroll internally so nothing is clipped on a 360×640
(the page itself still never scrolls, so the no-scroll rule holds).
Confirm this is the wanted order, or switch to the README's.
